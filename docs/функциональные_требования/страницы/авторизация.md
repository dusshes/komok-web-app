# Страница: Регистрация и Авторизация (Вход)

Этот раздел описывает процесс создания учетной записи пользователя и входа в систему.

## 1. Сценарий: Вход в систему (Авторизация)
Форма входа должна быть лаконичной:
* **Email** (текстовое поле, валидация формата почты, обязательное).
* **Пароль** (скрытое поле ввода, обязательное).
* **Кнопка «Войти»**.
* **Ссылка «Регистрация»** (ведет на форму создания аккаунта).
* **Кнопки OAuth (при наличии возможности):** Google, VK.

### 🔄 Перенаправление (Redirect / Next parameter):
Если пользователь попал на страницу входа принудительно (например, при клике на кнопку «Забронировать» из файла `Роли.md` п. 3.1), в URL передается параметр возврата, например: `/login?next=/book/item_id`.
После успешного входа система должна автоматически перенаправить пользователя по указанному пути, завершив бронирование.

## 2. Сценарий: Регистрация нового аккаунта
При создании аккаунта мы собираем максимум информации о клиенте, чтобы в будущем мочь связаться с ним для уточнения деталей, выдачи забронированных вещей или перевода заработанных денег.

### 📝 Список полей формы регистрации:
1. **Email** (обязательное) — уникальный адрес электронной почты.
2. **Пароль** (обязательное) — минимум 6 символов, скрытый ввод.
3. **Подтверждение пароля** (обязательное) — должно совпадать с полем «Пароль», скрытый ввод.
4. **Имя** (обязательное) — для обращения администратора.
5. **Страна** (выпадающий список) — выборка активных стран из таблицы `countries`. При выборе страны динамически обновляется список городов.
6. **Город** (выпадающий список) — выборка городов выбранной страны из таблицы `cities`.
7. **Контакты (мессенджеры) — пользователь должен заполнить хотя бы один из них:**
   * **WhatsApp** (текстовое поле ввода, телефонный формат).
   * **Telegram** (текстовое поле, никнейм).
   * **Zalo** (текстовое поле, телефон/ID для Вьетнама).
   * **Max** (текстовое поле для связи через сервис Max).
8. **Предпочитаемый способ связи** (выбор одного варианта / radio buttons):
   * `Email` / `WhatsApp` / `Telegram` / `Zalo` / `Max`.
9. **Куда перечислять выручку (Реквизиты)** (текстовое поле, необязательное при регистрации). Здесь пользователь может указать номер карты, кошелька или банка для будущих выплат при продаже вещей. Если не заполнено, система будет предупреждать при подаче заявки.

## 4. Сценарий: Верификация Email (через Resend)
Для повышения безопасности и предотвращения использования недействительных адресов, регистрация нового пользователя должна завершаться верификацией email.

### 📧 Процесс верификации:
1. **Отправка кода:**
   * После заполнения формы регистрации (п. 2), система создает запись пользователя в состоянии `pending` (неактивен) и отправляет 6-значный цифровой код на указанный email через сервис **Resend**.
   * Письмо должно содержать:
     * Тема: "Код подтверждения регистрации в Komok"
     * Текст: "Ваш код подтверждения: [XXXXXX]. Срок действия кода: 15 минут."
2. **Экран ввода кода:**
   * Пользователь перенаправляется на страницу `/verify-email`.
   * Форма содержит поле "Код подтверждения" (6 цифр) и кнопку "Подтвердить".
   * Предусмотрена кнопка "Отправить код повторно" (доступна через 60 секунд после предыдущей отправки).
3. **Валидация кода:**
   * Система проверяет:
     * Существование кода для данного пользователя.
     * Срок действия кода (15 минут).
     * Соответствие кода (сравнение хеша введенного кода с хешем в БД).
   * При успешной валидации:
     * Статус пользователя меняется на `active`.
     * Пользователь автоматически авторизуется и перенаправляется на главную страницу (или страницу, с которой он пришел).
   * При ошибке:
     * Отображается сообщение: "Неверный код" или "Код истек".

### ⚙️ Требования к хранению кодов:
* Коды должны храниться в базе данных в **хешированном виде** (например, используя bcrypt или argon2).
* Каждая запись кода должна содержать поле `expires_at` (timestamp).
* После успешного подтверждения или истечения срока действия, запись кода должна удаляться из базы.
