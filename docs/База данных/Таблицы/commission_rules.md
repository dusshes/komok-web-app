## 2.3. Таблица «Правила комиссий» (`commission_rules`)

Таблица определяет, какой процент или фиксированную сумму забирает себе магазин при продаже товара, в зависимости от ценового диапазона.

### Структура таблицы `commission_rules`
* `id` (SERIAL, Primary Key)
* `price_from` (NUMERIC(10, 2), Not Null) — нижняя граница стоимости товара (включительно).
* `price_to` (NUMERIC(10, 2), Nullable) — верхняя граница стоимости товара (null, если ограничений сверху нет).
* `fee_percent` (NUMERIC(5, 2), Default 0.00) — процент комиссии магазина (например, 15.00 для 15%).
* `fee_fixed` (NUMERIC(10, 2), Default 0.00) — фиксированная сумма комиссии в рублях (если применяется).
* `created_at` (TIMESTAMP, Default NOW())

### 📊 Пример заполнения таблицы (Бизнес-логика)
Администратор один раз через базу данных или админку заполняет сетку тарифов:
1. От 0 до 1 000 руб: комиссия **20%**
2. От 1 001 до 10 000 руб: комиссия **15%**
3. От 10 001 до 50 000 руб: комиссия **10%** + фиксированно **500 руб**
4. От 50 001 руб и выше: комиссия фиксированная — **5 000 руб** (`fee_percent = 0`, `price_to = null`).

---

### 🧮 Алгоритм расчета (SQL-логика для бэкенда)
Чтобы найти правило для конкретной цены `X`, бэкенд выполняет запрос:
```sql
SELECT fee_percent, fee_fixed 
FROM commission_rules 
WHERE :current_price >= price_from 
  AND (price_to IS NULL OR :current_price <= price_to)
LIMIT 1;
```
