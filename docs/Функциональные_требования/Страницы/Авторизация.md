# Страница: Регистрация и Авторизация (Вход)

Этот раздел описывает процесс создания учетной записи пользователя и входа в систему.

## 1. Сценарий: Вход в систему (Авторизация)
Форма входа должна быть лаконичной:
* **Email** (текстовое поле, валидация формата почты, обязательное).
* **Пароль** (скрытое поле ввода, обязательное).
* **Кнопка «Войти»**.
* **Ссылка «Регистрация»** (ведет на форму создания аккаунта).
* **Кнопки OAuth (при наличии возможности):** Google, VK.

### 🔄 Перенаправление (Redirect / Next parameter):
Если пользователь попал на страницу входа принудительно (например, при клике на кнопку «Забронировать» из файла `Роли.md` п. 3.1), в URL передается параметр возврата, например: `/login?next=/book/item_id`.
После успешного входа система должна автоматически перенаправить пользователя по указанному пути, завершив бронирование.

## 2. Сценарий: Регистрация нового аккаунта
При создании аккаунта мы собираем максимум информации о клиенте, чтобы в будущем мочь связаться с ним для уточнения деталей, выдачи забронированных вещей или перевода заработанных денег.

### 📝 Список полей формы регистрации:
1. **Email** (обязательное) — уникальный адрес электронной почты.
2. **Пароль** (обязательное) — минимум 6 символов, скрытый ввод.
3. **Имя** (обязательное) — для обращения администратора.
4. **Страна** (выпадающий список) — выборка активных стран из таблицы `countries`. При выборе страны динамически обновляется список городов.
5. **Город** (выпадающий список) — выборка городов выбранной страны из таблицы `cities`.
6. **Контакты (мессенджеры) — пользователь должен заполнить хотя бы один из них:**
   * **WhatsApp** (текстовое поле ввода, телефонный формат).
   * **Telegram** (текстовое поле, никнейм).
   * **Zalo** (текстовое поле, телефон/ID для Вьетнама).
   * **Max** (текстовое поле для связи через сервис Max).
7. **Предпочитаемый способ связи** (выбор одного варианта / radio buttons):
   * `Email` / `WhatsApp` / `Telegram` / `Zalo` / `Max`.
8. **Куда перечислять выручку (Реквизиты)** (текстовое поле, необязательное при регистрации). Здесь пользователь может указать номер карты, кошелька или банка для будущих выплат при продаже вещей. Если не заполнено, система будет предупреждать при подаче заявки.

## 3. Обработка ошибок и валидация (Edge Cases)
* **Проверка уникальности Email:** Если email уже занят, выводить сообщение: `«Этот Email уже зарегистрирован в системе»`.
* **Валидация пароля:** Пароль должен быть не короче 6 символов. Если короче: `«Пароль должен содержать не менее 6 символов»`.
* **Пустые обязательные поля:** При отправке подсвечивать красным пустые обязательные поля с текстом: `«Поле обязательно для заполнения»`.
* **Хотя бы один контакт:** Если поля WhatsApp, Telegram, Zalo и Max пустые, показывать общую ошибку у блока контактов: `«Пожалуйста, укажите хотя бы один способ связи (WhatsApp, Telegram, Zalo или Max)»`.
* **Ошибка входа:** При неверной паре email/пароль показывать общую ошибку: `«Неверный Email или пароль»`.
